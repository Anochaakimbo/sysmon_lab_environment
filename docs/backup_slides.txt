แต่บน Windows การเก็บ RegistryEvent ทุกตัวคือท่อน้ำ วัดจริง 1 รอบก่อนกรอง

    EventID 12 RegistryAddDelete    88,447   74.5%
    EventID 13 RegistrySetValue     19,895   16.7%

สิ่งที่ตัดออก และเหตุผล

       กรองตาม "path เต็มของ process" ไม่ได้กรองตามความน่าสงสัย
       -> registry event จาก process ผู้โจมตียังเก็บครบ 100%
       ต้องใช้ condition="is" path เต็ม ห้ามใช้ end with ชื่อไฟล์
       เพราะ T1036.003 ปลอม powershell เป็นชื่อ taskhostw.exe / lsass.exe

    2. EventType CreateKey             23,018 -> 1,776 events
       อ้างอิงจากการวัด NLME.csv ของเปเปอร์โดยตรง:
       EventID 12 ของเขาไม่มี CreateKey เลยสักแถว มีแต่ DeleteValue 1,126 + DeleteKey 20
       -> นี่คือการทำให้ตรงเปเปอร์ ไม่ใช่แค่ลดขนาดไฟล์

    3. EventID 255 ไม่ใช่ telemetry
       "The C:\Sysmon\ owner is not System. Archiving is disabled."
       ยิงทุกครั้งที่มี FileDelete (2,838 ครั้ง = จำนวน FileDelete พอดี) field อื่นว่างหมด
       ไม่แก้ ownership ที่ต้นทางเพราะการแก้จะเปิด archiving = Sysmon ก๊อปทุกไฟล์ที่ถูกลบ

C5  "enrichment คืออะไร ทำไมต้องทำ"
--------------------------------------------------------------------------------
ปัญหา: Sysmon ใส่ CommandLine / Hashes / Parent* มาเฉพาะ EventID 1 (ProcessCreate)
       event อื่น (FileCreate, NetworkConnect, RegistrySetValue) มีแต่ ProcessGuid

       event ที่ไม่ใช่ EventID 1 ทั้งหมด        58,014 แถว
       ถ้าไม่ enrich จะไม่มี CommandLine เลยทั้ง 58,014 แถว

วิธีทำ: สร้างตาราง ProcessGuid -> (CommandLine, Hashes, Parent*, User, ...)
        จาก EventID 1 แล้วเติมย้อนกลับเข้า event อื่นของ process เดียวกัน
        fallback เป็น ProcessId ถ้าไม่มี GUID

ผลลัพธ์ - ความครบของ field หลัง enrich

        field                Linux     Windows
        CommandLine          92.7%      71.7%
        Hashes               92.7%      76.2%
        ParentImage          73.5%      71.6%
        ParentCommandLine    73.5%      70.5%
        IntegrityLevel       92.7%      71.7%

        วิธีที่ match ได้: ตาม GUID 44,368 แถว / ตาม PID 246 แถว / ไม่ได้ 36,717 แถว

ข้อควรระวัง (enrichment leakage)
    process ที่เกิด "หลัง" Sysmon เริ่มทำงาน จะมี CommandLine
    daemon ที่เกิด "ก่อน" จะไม่มี
    ถ้า benign เป็น daemon ล้วน โมเดลจะเรียน "CommandLine ว่าง = benign"
    -> benign.sh / benign.ps1 จึงต้องสร้าง process ใหม่เยอะๆ ไม่ใช่ปล่อย idle

C6  "เก็บซ้ำได้ไหม / ควบคุมตัวแปรยังไง"
--------------------------------------------------------------------------------
ทุกรอบเก็บทำแบบเดียวกันหมด (orchestrator ทำให้อัตโนมัติ)

    1. revert snapshot "clean"        ทุกรอบ - เครื่องกลับสภาพเดิมเป๊ะ
    2. boot VM
    3. restart sysmon + rsyslog       จำเป็น! ดูด้านล่าง
    4. คัดลอก scenario ไป sandbox directory  (/tmp/lab_sandbox, C:\lab_sandbox)
    5. รัน scenario วนซ้ำจนครบ duration
    6. Atomic-Cleanup ล้าง artifact
    7. halt + parse -> enrich -> label

ทำไมต้อง restart sysmon หลังบูต (ข้อค้นพบที่เสียเวลาหาที่สุด)
    snapshot คืน memory state มาด้วย -> eBPF probe ของ Sysmon อยู่ในสภาพ stale
    FileCreate(11) + RawAccessRead(9) หายเกลี้ยงทั้งรอบ โดย event อื่นมาปกติ
    ไม่มี error ใดๆ  ->  restart แล้ว event 11 กลับมา 108 ตัวใน 15 วินาที
    (rsyslog ก็ต้อง restart ด้วยเหตุผลเดียวกัน - socket เก่าค้างจาก memory state)

การควบคุมความปลอดภัย
    deny list  T1490 T1485 T1561 T1529 T1491
    ทุก artifact อยู่ใน sandbox directory
    check_scenarios.py ตรวจ 6 อย่างก่อนเก็บ (exit 1 ถ้าเจอปัญหา)
    check_atomics.ps1 คัด test อันตรายออกอัตโนมัติ 5 tag
        DENY-TECH / DESTRUCTIVE / LOGKILL / REBOOT / GUIBLOCK

B4  "label มายังไง"
--------------------------------------------------------------------------------

    1. seed = process ที่รันจาก /tmp/lab_sandbox หรือ C:\lab_sandbox

    วัดแล้ว session mode ให้ malicious 100% ทั้งที่ lineage บอก 8.9%

    จึงต้องมีการแยกหลักฐาน 4 ระดับ (B3)

B8  "unsupervised ทำไมต่ำกว่าเปเปอร์ (0.71 vs 0.975)"
--------------------------------------------------------------------------------
คำตอบ: โปรโตคอลของเปเปอร์ทำให้ baseline สูงมากอยู่แล้ว
        เราวัดด้วยโปรโตคอลเดียวกับเขาแล้วได้ใกล้เคียง

    โปรโตคอลเปเปอร์ (Fig.4): เทรน benign, เทส benign ที่เหลือ + malware ทั้งหมด
    -> test set เป็น malware 83%

        model                          prec    rec     F1      AUC
        LOF ของเรา (โปรโตคอลเดียวกัน)  0.976   0.805   0.882   0.917
        LOF ของเปเปอร์                 0.958   0.993   0.975   ไม่รายงาน
        baseline "flag ทุกแถว"         0.832   1.000   0.908   -

    -> detector ที่ตอบว่าผิดปกติทุกแถวโดยไม่คิดอะไร ได้ F1 0.908

ข้อสังเกตเพิ่ม
    One-Class SVM ของเปเปอร์ recall = 1.0000 พอดีเป๊ะ precision 0.7411
    ซึ่งเท่ากับสัดส่วน malware ใน test set ของเขา = flag ทุกแถว
    LOF ของเขาใช้ feature เดียวได้ F1 0.9778 = สัญญาณของ feature ที่รั่ว label

    -> เราจึงรายงาน AUC คู่เสมอ และพิมพ์ baseline คู่ทุกตาราง

B14  "ปิด Windows Defender แล้วผลเปลี่ยนไปแค่ไหน"

Tamper Protection ทำให้ Set-MpPreference -Disable* ถูกย้อนกลับเงียบๆ
ตรวจด้วย Get-MpThreatDetection พบว่า Defender บล็อก command line ของ test ที่โหลดไฟล์

    NetworkConnect รวม           77             121
    NetworkConnect malicious      0               6
    events รวม                 1,776           1,894
    FileCreate %mal             46.2%           56.4%

ถ้าไม่ปิด NetworkConnect จะกลายเป็น "benign เสมอ" = leakage ตรงๆ
-> ต้องเขียนในธีสิสว่าปิด Defender และ Tamper Protection เพราะกระทบ event ที่เก็บได้
