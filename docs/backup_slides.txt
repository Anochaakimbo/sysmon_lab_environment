B4  "label มายังไง"
--------------------------------------------------------------------------------
คำตอบ: lineage labeling
    1. seed = process ที่รันจาก /tmp/lab_sandbox หรือ C:\lab_sandbox
    2. ไล่ ParentProcessGuid ลงไปหาลูกหลานทั้งหมด
    3. ทุก event ของ process ในสายนั้น = label 1

ทำไมไม่ใช้ "ทั้ง session ที่รันมัลแวร์ = malicious"
    วัดแล้ว session mode ให้ malicious 100% ทั้งที่ lineage บอก 8.9%
    -> โมเดลจะเรียน "ช่วงเวลา" ไม่ใช่พฤติกรรม

ข้อจำกัดที่ยอมรับ
    label=1 แปลว่า "สืบสายจาก sandbox" ไม่ได้แปลว่า event นั้นเป็นมัลแวร์ในตัวเอง
    จึงต้องมีการแยกหลักฐาน 4 ระดับ (B3)

    ให้ RF ทำนาย platform ด้วย feature ชุดเดียวกัน (32 ตัวสะอาด)

ทางออกที่เลือก: รายงานทั้งแบบรวมและแบบแยก ให้ผู้อ่านตัดสินเอง

B7  "ทำ feature selection ไหม / PCA ทำหรือยัง"
--------------------------------------------------------------------------------
คำตอบ: ทำแล้ว 3 วิธี ผลคือ PCA ไม่ช่วยกับ dataset นี้

1) PCA sweep n=1..30 (เลือกจาก validation ที่แยกจาก test)
        level             n ดีสุด   test F1   ไม่ใช้ PCA
        process (35)        18      0.9575     0.9579
        event   (48)        29      0.9355     0.9512

   n ที่ชนะเกือบเท่าจำนวนเต็ม = PCA ไม่ได้รวบอะไร
   เหตุผล: feature ผ่าน label encoding / ความยาวสตริงมาแล้ว
           ไม่มีความสัมพันธ์เชิงเส้นให้รวบ (ต่างจากเปเปอร์ที่มีแพลตฟอร์มเดียว)

2) greedy backward elimination
        ตัดได้ 30 จาก 35 และ 44 จาก 48 โดยเสีย F1 ไม่ถึง 1%

3) ตัด feature ที่รั่ว 6 ตัว (--drop-derived)
        CurrentDirectory  /tmp/lab_sandbox = malicious 100%
                          <- seed directory ของตัว labeler เอง
        ancestor_depth    มาจาก lineage tree เดียวกับที่สร้าง label
        img_len           เปเปอร์ตัด Image เองเพราะรั่ว label

B8  "unsupervised ทำไมต่ำกว่าเปเปอร์ (0.71 vs 0.975)"
--------------------------------------------------------------------------------
คำตอบ: โปรโตคอลของเปเปอร์ทำให้ baseline สูงมากอยู่แล้ว
        เราวัดด้วยโปรโตคอลเดียวกับเขาแล้วได้ใกล้เคียง

    โปรโตคอลเปเปอร์ (Fig.4): เทรน benign, เทส benign ที่เหลือ + malware ทั้งหมด
    -> test set เป็น malware 83%

        model                          prec    rec     F1      AUC
        LOF ของเรา (โปรโตคอลเดียวกัน)  0.976   0.805   0.882   0.917
        LOF ของเปเปอร์                 0.958   0.993   0.975   ไม่รายงาน
        baseline "flag ทุกแถว"         0.832   1.000   0.908   -

    -> detector ที่ตอบว่าผิดปกติทุกแถวโดยไม่คิดอะไร ได้ F1 0.908

ข้อสังเกตเพิ่ม
    One-Class SVM ของเปเปอร์ recall = 1.0000 พอดีเป๊ะ precision 0.7411
    ซึ่งเท่ากับสัดส่วน malware ใน test set ของเขา = flag ทุกแถว
    LOF ของเขาใช้ feature เดียวได้ F1 0.9778 = สัญญาณของ feature ที่รั่ว label

    -> เราจึงรายงาน AUC คู่เสมอ และพิมพ์ baseline คู่ทุกตาราง

B14  "ปิด Windows Defender แล้วผลเปลี่ยนไปแค่ไหน"
--------------------------------------------------------------------------------
Tamper Protection ทำให้ Set-MpPreference -Disable* ถูกย้อนกลับเงียบๆ
ตรวจด้วย Get-MpThreatDetection พบว่า Defender บล็อก command line ของ test ที่โหลดไฟล์

                            Defender เปิด    Defender ปิด
    NetworkConnect รวม           77             121
    NetworkConnect malicious      0               6
    events รวม                 1,776           1,894
    FileCreate %mal             46.2%           56.4%

ถ้าไม่ปิด NetworkConnect จะกลายเป็น "benign เสมอ" = leakage ตรงๆ
-> ต้องเขียนในธีสิสว่าปิด Defender และ Tamper Protection เพราะกระทบ event ที่เก็บได้
