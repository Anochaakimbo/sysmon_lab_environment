====================================================================================
ข้อจำกัด - ทำไมตัวเลขถึงยังไม่น่าเชื่อถือเท่าที่ควร
====================================================================================

1. HARNESS LEAKAGE - โมเดลเรียน 'คำสั่งยาว = มัลแวร์' ไม่ใช่พฤติกรรม
   ความยาว CommandLine  median: benign 22  vs  malicious 76
   ใช้เงื่อนไข 'ความยาว > 79' อย่างเดียวไม่ต้องมีโมเดล ได้ accuracy 0.7603
   (ทายคลาสใหญ่อย่างเดียวได้ 0.6619)
   สาเหตุ: Atomic Red Team เรียกทุกอย่างผ่าน PowerShell พร้อม argument ยาว
           ส่วน benign เป็นคำสั่งสั้น -> ความยาวกลายเป็นลายเซ็นของเครื่องมือทดสอบ
   แก้: ทำ benign ให้มีคำสั่งยาวพอกัน ไม่ใช่ตัด CommandLine ทิ้ง

2. เก็บแค่รอบเดียวต่อ scenario (12 รอบ / 12 scenario)
   -> ทำ cross-validation แบบกันไว้ 1 รอบไม่ได้ จึงไม่มี error bar
   -> ตอบไม่ได้ว่า 'รันซ้ำแล้วผลเหมือนเดิมไหม'
   แก้: เก็บซ้ำ 3 รอบต่อ scenario (กดรันใหม่ ไม่ใช่ยืด duration) ~9 ชม.

3. ความหลากหลายของสภาพแวดล้อมต่ำ - 2 เครื่อง, user เดียว, workgroup
   เปเปอร์อ้างอิงใช้ 5 เครื่องใน AD domain เก็บต่อเนื่อง 31 ชม.
   -> โมเดลอาจเรียนลักษณะเฉพาะของเครื่องนี้ ไม่ใช่ของมัลแวร์

4. label มาจาก lineage ไม่ใช่การวิเคราะห์ทีละ event  (lineage 62,035, session 19,296)
   label=1 แปลว่า 'สืบสายจาก process ที่รันในแซนด์บ็อกซ์'
   บาง event จึงเป็นกิจกรรมปกติของ OS ที่ติด label มาด้วย
   วัดแล้ว (trojan_win): มีหลักฐานตรงในตัว event เอง 45.5% / ติดเพราะสายเลือดล้วน 22.6%

5. ต้องตัด feature ที่รั่ว 6 ตัวออกก่อนเทรน (--drop-derived)
   CurrentDirectory: /tmp/lab_sandbox = malicious 100%  <- seed dir ของตัว labeler เอง
   ancestor_depth  : มาจาก lineage tree เดียวกับที่สร้าง label
   img_len         : เปเปอร์ตัด Image ทิ้งเองเพราะรั่ว label
   ถ้าไม่ตัด F1 จะสูงกว่านี้ ~2 จุด แต่เป็นตัวเลขที่ป้องกันตัวไม่ได้

6. ที่ระดับ event เดี่ยวๆ มัลแวร์หน้าตาเหมือน benign
   powershell เขียนไฟล์ 1 ไฟล์ ไม่มีอะไรบอกได้ว่าอันตราย
   จึงต้องรวมเป็น process-level ก่อน (F1 ต่างกันประมาณ 0.11)

====================================================================================
สรุปสิ่งที่จะทำต่อ
====================================================================================
1. เก็บซ้ำ 3 รอบต่อ scenario -> รายงานเป็น mean +/- sd
2. เพิ่มความหลากหลายของ benign โดยเฉพาะคำสั่งยาว เพื่อลบ harness leakage
3. เพิ่ม feature เชิงพฤติกรรม (entropy ชื่อไฟล์, จำนวน child process,
   ความสม่ำเสมอของช่วงเวลา network connect) แทนการพึ่งความยาวคำสั่ง
4. ขยายเป็นหลายเครื่อง เพื่อตัดข้อครหาว่าโมเดลจำเครื่องเดียว
