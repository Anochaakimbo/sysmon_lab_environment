# การประเมินผลแยก Linux และ Windows

ไฟล์ใหม่ `ml_revised_by_os.py` ใช้ `revised_experiments.py` เป็นฐาน คงการสร้างฟีเจอร์ โมเดล การแบ่งข้อมูล scaler และ threshold แล้วคำนวณเมตริกแยก OS จากผลทำนายชุดทดสอบเดียวกัน ไม่ได้ฝึกโมเดลแยก OS และไม่ได้ทดสอบการถ่ายโอนจาก OS หนึ่งไปอีก OS หนึ่ง

## ไฟล์ใดตรงกับบทความล่าสุด

| ไฟล์ | หน้าที่และความสัมพันธ์กับบทความ |
|---|---|
| ml_train.py | โค้ดฝึกเดิม แบ่ง GroupShuffleSplit; threshold โหมดหลักเลือกจาก mixed-label validation ไม่ใช่โปรโตคอล P1 5×5 |
| ml_benchmark.py | เปรียบเทียบวิธีแบ่งข้อมูล ใช้ RF 150 ต้นและ Linear SVM ต่างจากการทดลองล่าสุด |
| ml_feature_study.py | ศึกษาฟีเจอร์/PCA ไม่ใช่โค้ดตารางผลหลัก 7 โมเดล |
| ml_showcase.py | รวมการทดลองสำหรับแสดงผล เรียก ml_train และใช้ contamination 0.3 ไม่ใช่ calibration ล่าสุด |
| ml_predict.py | โหลดโมเดลที่บันทึกไว้เพื่อทำนาย ไม่ได้สร้างการประเมิน 5×5 |
| **revised_experiments.py** | **ตรงกับวิธีล่าสุด**: composite key, lineage CV 5×5, 32 ฟีเจอร์, SVM cap 8,000, benign calibration 80:20 ที่เปอร์เซ็นไทล์ 95 และ P2–P4 |

เอกสาร `docs/revision_v6_notes.md` ระบุว่า revised_experiments.py ใช้สร้าง RF F1 0.920±0.008 และ LOF AUC 0.839±0.016 การระบุนี้เป็นหลักฐานจากบันทึกโครงการ ส่วนผลรันใหม่ให้ดูตารางที่สร้างจริง เพราะเวอร์ชันไลบรารีอาจต่างจากเดิม

## ข้อมูล

ใช้ `FINAL_DATASET.csv` ที่รากโครงการเป็นค่าเริ่มต้น มี 81,331 แถว 80 คอลัมน์ ข้อมูล 79 คอลัมน์เดิมตรงกับไฟล์ `D:/work y4/project1/code/merged_dataset.csv` ทุกค่า และเพิ่ม run_id ของ 12 รอบทดลองมาอีกคอลัมน์ โค้ดใหม่ไม่สร้าง run_id ขึ้นเองเมื่อขาด

## วิธีรัน

รันจากโฟลเดอร์ sysmon_lab_environment ด้วย Python ที่มี numpy, pandas, scipy และ scikit-learn:

```powershell
python host/ml_revised_by_os.py --protocols p1
```

P1 ใช้ 5 fold ซ้ำ 5 ครั้งตามค่าเริ่มต้น ถ้าต้องการ P2 และ P3 ด้วย:

```powershell
python host/ml_revised_by_os.py --protocols p1 p2 p3 --out reference/revised_by_os_all
```

หากต้องการเก็บผลทำนายรายโปรเซสเพิ่ม `--save-predictions` (ไฟล์อาจมีขนาดใหญ่)

P4 ต้องให้ไฟล์ labeled CSV ของสองรอบใหม่ด้วย `--extra file1.csv file2.csv` แต่ละไฟล์ต้องมี run_id เดียวและไม่ซ้ำกับข้อมูลฝึก ไม่ควรใช้ข้อมูลเดิมแทนรอบใหม่

โฟลเดอร์ผลลัพธ์ต้องว่างหรือยังไม่มี เพื่อป้องกันการผสมผลคนละการทดลอง

## ไฟล์ผลลัพธ์

- `p1_by_os.csv`: ผลราย fold ของ ALL, linux และ windows มี Accuracy, Precision, Recall, F1, FPR, AUC, TN, FP, FN, TP, จำนวนตัวอย่าง/คลาส และ threshold
- `p1_summary_by_os.csv`: ค่าเฉลี่ยและ SD ของเมตริกแยก OS จาก 25 fold ไม่ใช่ค่าเฉลี่ยของสอง OS และ SD ไม่ใช่ช่วงความเชื่อมั่น
- `manifest.json`: คำสั่ง พารามิเตอร์ hash ข้อมูล/โค้ด เวอร์ชันไลบรารี จำนวนโปรเซสและฟีเจอร์
- `p1_predictions.csv`: ผลทำนายพร้อม process key, run, lineage, label และ score เมื่อเปิดตัวเลือกบันทึก
- P2–P4 ใช้ชื่อไฟล์ตามหมายเลขโปรโตคอล ผล P4 แยกผลรวมสองรอบออกจากผลรายรอบ ไม่เฉลี่ยรายการที่ซ้อนกัน

`n_test` ที่รับมาจากโค้ดเดิมคือขนาดชุดทดสอบทั้ง fold ส่วน `N`, `N0`, `N1` คือจำนวนของ OS ในแถวนั้น ค่า AUC ว่างเมื่อ subset มีคลาสเดียว และ FPR ว่างเมื่อไม่มีตัวอย่าง label=0

## ข้อจำกัดที่ต้องอธิบายในบทความ

Scaler ของโค้ดเดิม fit จาก outer training ทั้งหมดก่อนแยก benign fit/calibration ดังนั้นยืนยันได้ว่าตัว anomaly detector และการเลือก threshold ใช้ benign แต่ไม่ควรกล่าวว่าทั้ง pipeline เรียนรู้จาก benign เท่านั้น โค้ดใหม่นี้คงขั้นตอนดังกล่าวไว้เพื่อเปรียบเทียบกับผลเดิม การแก้ scaler ต้องจัดเป็นการทดลองใหม่

Threshold ของ anomaly ใช้ `-score_samples` จาก benign calibration ที่เปอร์เซ็นไทล์ 95 และทำนาย 1 เมื่อ score > threshold ใช้ threshold เดียวกันทั้ง Linux และ Windows ภายใน fold

การมีโค้ดและ dataset ยังไม่ยืนยันความถูกต้องของ label กับกิจกรรมจริงโดยอิสระ และผล P1 ไม่แทนผลทดสอบกับเครื่องหรือมัลแวร์จริง

## ผลตรวจและผลรันวันที่ 5 ตุลาคม 2569

รัน P1 ครบ 25 fold ด้วย FINAL_DATASET.csv ได้ 23,971 โปรเซส 5,072 กลุ่มสายโปรเซส และ 32 ฟีเจอร์ ผลอยู่ที่ `reference/revised_by_os/` ตรวจแล้ว 600 แถว (8 วิธีรวม baseline × 3 ขอบเขต OS × 25 fold) จำนวนตัวอย่างและ confusion matrix แยก OS รวมกลับได้ตรง ALL ทุก fold และ threshold ของ anomaly เหมือนกันทุก OS ภายใน fold

| โมเดล | OS | F1 เฉลี่ย±SD | FPR เฉลี่ย | ROC-AUC เฉลี่ย±SD |
|---|---|---|---|---|
| Random Forest | รวม | 0.918700±0.008941 | 0.044286 | 0.985886±0.002655 |
| Random Forest | Linux | 0.908975±0.019306 | 0.039115 | 0.984051±0.002996 |
| Random Forest | Windows | 0.934336±0.022528 | 0.063923 | 0.988066±0.004814 |
| Local Outlier Factor | รวม | 0.453096±0.062570 | 0.049147 | 0.838739±0.015807 |
| Local Outlier Factor | Linux | 0.425341±0.048716 | 0.048701 | 0.824131±0.016698 |
| Local Outlier Factor | Windows | 0.520319±0.135661 | 0.050958 | 0.873007±0.039376 |

ผลรวมรอบนี้ยังไม่ตรงตัวเลขเดิมทุกค่า: RF F1 ประมาณ 0.919±0.009 เทียบกับ 0.920±0.008 ในบทความ ส่วน LOF AUC ปัดสามตำแหน่งตรงที่ 0.839±0.016 แต่ LOF F1 รอบนี้ 0.453±0.063 ต่างจาก 0.462±0.064 เดิม จึงยืนยันได้ว่าเลือกโค้ดตรงวิธีทดลองและมีบันทึกโครงการเชื่อมโยงกับผลเดิม แต่ยังยืนยันการทำซ้ำคะแนนเดิมทุกค่าไม่ได้ ต้องเทียบเวอร์ชันไลบรารีและไฟล์ผลราย fold เดิมก่อนสรุปสาเหตุ ห้ามนำผล OS รอบนี้ไปจับคู่กับคะแนนรวมเดิมเสมือนเป็นการรันเดียวกัน

ทดสอบฟังก์ชัน evaluate เดิมเทียบกับโค้ดใหม่ในข้อมูลทดสอบควบคุมแล้ว ผลรวมทุกเมตริกตรงกันครบ 7 โมเดล รวมทั้งทดสอบ OS ที่มีคลาสเดียว (AUC ว่าง) และไม่มีข้อมูลปกติ (FPR ว่าง) ไม่ได้รัน P2–P4 ในครั้งนี้
