P005 งานวิจัยด้านการตรวจจับมัลแวร์ด้วยการเรียนรู้ของเครื่องส่วนใหญ่อาศัยบันทึกเหตุการณ์จากระบบปฏิบัติการ Windows เพียงแพลตฟอร์มเดียว บทความนี้นำเสนอการสร้างชุดข้อมูลสำหรับตรวจจับมัลแวร์จากบันทึกเหตุการณ์ Sysmon แบบสองแพลตฟอร์มคู่ขนานคือ Linux และ Windows โดยจำลองพฤติกรรมด้วยชุดทดสอบ Atomic Red Team ครอบคลุม 6 ประเภทสถานการณ์ ได้แก่ พฤติกรรมปกติ เรียกค่าไถ่ โทรจัน บอตเน็ต ขุดเหรียญ และการใช้ช่องโหว่ ชุดข้อมูลที่ได้มีทั้งสิ้น 81,331 เหตุการณ์ (Linux 45,311 และ Windows 36,020) มีสัดส่วนตัวอย่างอันตราย 33.8% ใกล้เคียงกันทั้งสองแพลตฟอร์ม การกำหนดป้ายกำกับใช้การสืบสายกระบวนการจากไดเรกทอรีทดสอบ ผลการทดลองพบว่าเมื่อประเมินด้วยการแบ่งข้อมูลแบบ GroupKFold ตามกระบวนการเพื่อป้องกันการรั่วไหลของข้อมูล แบบจำลอง Random Forest ระดับกระบวนการให้ความแม่นยำ 94.9% และค่า F1 เท่ากับ 0.924 ขณะที่แบบจำลองไม่มีผู้สอน Local Outlier Factor ให้พื้นที่ใต้เส้นโค้ง 0.849 บทความนี้ยังวิเคราะห์แหล่งการรั่วไหลของข้อมูลอย่างเป็นระบบ และชี้ให้เห็นว่าโปรโตคอลการประเมินมีผลต่อค่าที่รายงานมากกว่าปริมาณข้อมูล
P006 คำสำคัญ -- การตรวจจับมัลแวร์, Sysmon, การเรียนรู้ของเครื่อง, ชุดข้อมูลข้ามแพลตฟอร์ม, การรั่วไหลของข้อมูล
P007 ABSTRACT
P008 Most machine-learning malware-detection studies rely on host telemetry from a single operating system, typically Windows. This paper presents the construction of a malware-detection dataset from Sysmon event logs across two parallel platforms, Linux (Sysmon for Linux) and Windows, using Atomic Red Team to emulate six behavioral scenarios: benign, ransomware, trojan, botnet, cryptominer, and exploitation. The resulting dataset contains 81,331 events (45,311 on Linux and 36,020 on Windows) with a 33.8% malicious ratio that is nearly identical on both platforms. Labels are assigned by process lineage traced from a controlled sandbox directory. Under a leakage-controlled GroupKFold protocol (grouped by process), a process-level Random Forest attains 94.9% accuracy and an F1 of 0.924, while the unsupervised Local Outlier Factor reaches an AUC of 0.849. We further analyze the leakage sources that would otherwise inflate reported accuracy, and show that the evaluation protocol affects the reported figures more than the amount of data.
P009 Keywords -- malware detection, Sysmon, machine learning, cross-platform dataset, data leakage
P010 1. บทนำ
P011 การเปลี่ยนผ่านสู่ยุคดิจิทัลทำให้ภัยคุกคามจากมัลแวร์ทวีความรุนแรงและตรวจจับได้ยากขึ้น สถิติของหน่วยงานด้านความมั่นคงปลอดภัยไซเบอร์ในหลายประเทศชี้ว่าจำนวนเหตุการณ์โจมตีเพิ่มขึ้นต่อเนื่องทุกปี การเฝ้าระวังแบบอาศัยลายเซ็น (signature-based) เพียงอย่างเดียวจึงตามไม่ทันมัลแวร์รูปแบบใหม่ ทำให้การตรวจจับเชิงพฤติกรรมด้วยการเรียนรู้ของเครื่อง (machine learning) ได้รับความสนใจอย่างกว้างขวาง [1], [8]
P012 เครื่องมือ System Monitor (Sysmon) เป็นแหล่งบันทึกเหตุการณ์ระดับโฮสต์ที่ให้รายละเอียดของการสร้างกระบวนการ การเชื่อมต่อเครือข่าย และการเข้าถึงไฟล์อย่างครบถ้วน [20] งานวิจัยอ้างอิงหลักของบทความนี้ [1] ได้สร้างชุดข้อมูลและเปรียบเทียบแบบจำลอง 7 ชนิดจากบันทึก Sysmon บนระบบ Windows และรายงานว่าแบบจำลอง Random Forest ให้ค่า F1 ที่ 0.8868 อย่างไรก็ตาม งานดังกล่าวมีข้อจำกัดสองประการที่บทความนี้มุ่งแก้ไข ประการแรก ชุดข้อมูลครอบคลุมเฉพาะระบบปฏิบัติการ Windows ทำให้ไม่สามารถประเมินได้ว่าคุณลักษณะที่ใช้ตรวจจับยังใช้ได้กับแพลตฟอร์มอื่นหรือไม่ ซึ่งมีหลักฐานว่าการโอนย้ายแบบจำลองข้ามระบบปฏิบัติการทำให้ค่า F1 ลดลงอย่างมีนัยสำคัญ [4] ประการที่สอง งานดังกล่าวระบุเองว่าบันทึกที่ใช้ขาดความสัมพันธ์แบบกระบวนการแม่–ลูก (parent–child correlation) ซึ่งเป็นข้อมูลสำคัญต่อการวิเคราะห์เชิงพฤติกรรม [11]
P013 บทความนี้มีส่วนสนับสนุน (contribution) สี่ประการ (1) สร้างชุดข้อมูล Sysmon แบบสองแพลตฟอร์มคู่ขนาน (Linux และ Windows) ภายใต้วิธีการเก็บและกำหนดป้ายกำกับเดียวกัน (2) เพิ่มคุณลักษณะความสัมพันธ์กระบวนการแม่–ลูกและบรรทัดคำสั่งที่งานอ้างอิงไม่มี (3) ครอบคลุมเหตุการณ์การเชื่อมต่อเครือข่าย (NetworkConnect) สำหรับพฤติกรรม C2/beaconing ซึ่งชุดข้อมูลอ้างอิงแทบไม่มี (เพียง 20 เหตุการณ์) และ (4) วิเคราะห์แหล่งการรั่วไหลของข้อมูล (data leakage) อย่างเป็นระบบตามข้อเสนอแนะเชิงระเบียบวิธีในงาน [2], [3] และแสดงให้เห็นว่าโปรโตคอลการประเมินมีผลต่อค่าความแม่นยำที่รายงานมากกว่าปริมาณข้อมูล
P014 2. งานที่เกี่ยวข้อง
P015 2.1 การตรวจจับมัลแวร์จากบันทึกเหตุการณ์และ Sysmon
P016 การตรวจจับมัลแวร์เชิงพฤติกรรมจากบันทึกเหตุการณ์ระดับโฮสต์เป็นแนวทางที่ได้รับการศึกษาอย่างต่อเนื่อง งานอ้างอิงหลัก [1] เก็บบันทึก Sysmon จากเครื่อง 5 เครื่องในโดเมน Active Directory ต่อเนื่องประมาณ 31 ชั่วโมง และรวมศูนย์ผ่าน Windows Event Forwarding ได้ชุดข้อมูล NLME จำนวน 71,017 เหตุการณ์ จากนั้นเลือกคุณลักษณะด้วย Principal Component Analysis (PCA) และเปรียบเทียบแบบจำลองแบบมีผู้สอนและไม่มีผู้สอน งาน [5] เสนอระบบวิเคราะห์มัลแวร์แบบพลวัตด้วย Sysmon ร่วมกับ Elastic Stack และสร้างชุดข้อมูล AAU_MalData จากการวิเคราะห์มัลแวร์ 2,800 ตัวอย่าง โดยเชื่อมโยงเหตุการณ์กับกรอบ MITRE ATT&CK [21] แนวทางเหล่านี้ยืนยันว่า Sysmon เป็นแหล่งข้อมูลพฤติกรรมบนเครื่องที่เหมาะสมต่อการเรียนรู้ของเครื่อง
P017 2.2 ชุดข้อมูลเชิงพลวัตและการวิเคราะห์เชิงพฤติกรรม
P018 Sgandurra และคณะ [6] เสนอ EldeRan สำหรับจำแนก Ransomware โดยใช้ Cuckoo Sandbox เก็บพฤติกรรมขณะทำงาน เช่น การเรียก Windows API และการดำเนินการกับ Registry ไฟล์ และไดเรกทอรี งาน [7] สร้างชุดข้อมูลคุณลักษณะเชิงพลวัตสำหรับตรวจจับ Ransomware และเปรียบเทียบแบบจำลองหลายชนิด ส่วนงาน [8] แสดงการใช้การเรียนรู้เชิงลึกกับข้อมูลมัลแวร์ บทความนี้นำแนวคิด Host Behavioral Features มาประยุกต์กับ Sysmon Event Logs โดยตรง แทนการใช้ Cuckoo Sandbox เพื่อให้ได้ข้อมูลระดับกระบวนการที่ละเอียดและใกล้เคียงการใช้งานจริง
P019 2.3 การวิเคราะห์ระดับกระบวนการและข้ามแพลตฟอร์ม
P020 งาน [9] แสดงว่าการวิเคราะห์ในระดับกระบวนการ (process-level) ให้ผลดีกว่าระดับเครื่อง (machine-level) โดยได้ค่า F1 ที่ 0.87 พร้อมอัตราการแจ้งเตือนผิดต่ำ แม้มีโปรแกรมพื้นหลังทำงานพร้อมกัน ด้านความแตกต่างข้ามระบบปฏิบัติการ งาน BarongTrace [4] สร้างชุดข้อมูลมัลแวร์บน Linux ด้วย Sysmon for Linux และพบว่าเมื่อใช้แบบจำลองที่ฝึกจากข้อมูล Windows ไปทำนายข้อมูล Linux ค่า F1 ลดลงได้ถึง 0.54 ซึ่งยืนยันว่าข้อมูลจากสองระบบปฏิบัติการมีลักษณะต่างกัน และเป็นเหตุผลที่บทความนี้ออกแบบคุณลักษณะเชิงพฤติกรรมกลางระดับกระบวนการ
P021 2.4 อคติในการประเมินและการรั่วไหลของข้อมูลในความมั่นคงปลอดภัยเชิงเรียนรู้
P022 Arp และคณะ [2] ทบทวนงานด้านความมั่นคงปลอดภัยเชิงเรียนรู้ 30 บทความ และชี้ให้เห็นกับดักที่พบบ่อย เช่น การรั่วไหลของข้อมูล (data snooping) การเลือกตัวอย่างที่ไม่เป็นตัวแทน และการวัดผลที่ทำให้ค่าดูสูงเกินจริง ส่วน Pendlebury และคณะ [3] เสนอกรอบ TESSERACT เพื่อขจัดอคติเชิงพื้นที่และเชิงเวลาในการจำแนกมัลแวร์ บทความนี้นำข้อเสนอแนะดังกล่าวมาปฏิบัติโดยตรง ด้วยการรายงานผลภายใต้การแบ่งข้อมูลแบบจัดกลุ่มตามกระบวนการ (GroupKFold) และการประเมินแบบกันสถานการณ์ออก (leave-one-scenario-out) เพื่อจำลองการเผชิญภัยที่ไม่เคยพบ
P023 2.5 การตรวจจับด้วยข้อมูลสืบสาย (Provenance)
P024 แนวคิดการใช้ความสัมพันธ์เชิงสืบสายของกระบวนการเพื่อตรวจจับภัยคุกคามขั้นสูงมีงานรองรับ เช่น UNICORN [10] ที่ใช้กราฟสืบสาย (provenance graph) ตรวจจับ Advanced Persistent Threat แบบไม่ต้องมีลายเซ็น และ Kairos [11] ที่ตรวจจับและสืบสวนการบุกรุกจากประวัติการทำงานทั้งระบบ บทความนี้นำหลักการสืบสายกระบวนการมาใช้ในขั้นการกำหนดป้ายกำกับ โดยระบุว่าเหตุการณ์ใดสืบสายมาจากกระบวนการที่ถูกปล่อยในไดเรกทอรีทดสอบ

P029 3.1 สภาพแวดล้อมการทดลอง
P030 การทดลองดำเนินบนเครื่องโฮสต์ Windows 11 และใช้ VMware Workstation ร่วมกับ Vagrant ในการจัดการเครื่องเสมือน เครื่องเป้าหมายฝั่ง Linux ใช้ Ubuntu 22.04 ติดตั้ง Sysmon for Linux (schema 4.81) ส่งบันทึกผ่าน journald → rsyslog → TCP ไปยังตัวรับบนโฮสต์ ส่วนเครื่องเป้าหมายฝั่ง Windows ติดตั้ง Sysmon และส่งออกบันทึกในรูปแบบ EVTX เนื่องจากทรัพยากรหน่วยความจำจำกัด จึงรันเครื่องเสมือนทีละเครื่องแบบลำดับ (sequential) และคืนสภาพ (revert snapshot) ก่อนเริ่มทุกสถานการณ์เพื่อความสามารถในการทำซ้ำ ทั้งพฤติกรรมปกติและพฤติกรรมอันตรายถูกเก็บบนเครื่องเดียวกันเพื่อป้องกันการรั่วไหลระดับเครื่อง (VM leakage) [2]
P031 3.2 การจำลองพฤติกรรมและสถานการณ์
P032 ใช้ Atomic Red Team [22] จำลองเทคนิคตามกรอบ MITRE ATT&CK [21] โดยรันชุดทดสอบบนเครื่องเป้าหมายเอง และใช้เซิร์ฟเวอร์จำลอง Command-and-Control และ Mining Pool ภายในแล็บสำหรับพฤติกรรมเชิงเครือข่าย แบ่งเป็น 6 ประเภทสถานการณ์ต่อแพลตฟอร์ม (ตาราง 1) การเลือกมัลแวร์ห้าตระกูลนี้จงใจให้ครอบคลุมพฤติกรรมโฮสต์ที่แตกต่างกัน ได้แก่ การกระทำต่อไฟล์จำนวนมาก (ransomware) การคงอยู่และแก้ registry (trojan) การติดต่อเครือข่ายซ้ำ (botnet) การใช้ทรัพยากรต่อเนื่องพร้อมต่อ pool (miner) และการยกระดับสิทธิ์/แทรกโค้ด (exploit) ทำให้ชุดข้อมูลไม่ลำเอียงไปยังเหตุการณ์ชนิดใดชนิดหนึ่ง

P036 3.3 ท่อประมวลผลข้อมูล
P037 บันทึกดิบถูกแปลงผ่านขั้นตอน parse → enrich → label ได้แก่ (1) แยกวิเคราะห์ XML เป็นตาราง (2) เติมข้อมูลระดับกระบวนการ เช่น บรรทัดคำสั่ง ค่าแฮช และกระบวนการแม่ และ (3) กำหนดป้ายกำกับ จากนั้นรวมทุกรอบทดลองเป็นชุดข้อมูลเดียวโดยคงคอลัมน์ระบุแพลตฟอร์ม เครื่อง และรอบทดลองไว้เพื่อการตรวจสอบย้อนกลับ
P038 3.4 การกำหนดป้ายกำกับด้วยการสืบสายกระบวนการ
P039 ป้ายกำกับ (label = 1 คืออันตราย) กำหนดโดยการสืบสายกระบวนการ (process lineage): เหตุการณ์ใดที่สืบสายมาจากกระบวนการที่ถูกปล่อยจากไดเรกทอรีทดสอบจะถูกกำกับเป็นอันตราย แนวทางนี้สอดคล้องกับการตรวจจับด้วยข้อมูลสืบสาย [10], [11] และให้ผลแม่นยำกว่าการกำหนดตามช่วงเวลา (session labeling) ซึ่งเคยวัดพบว่ากำหนดป้ายผิดสูง อย่างไรก็ตาม การมีป้ายกำกับว่าอันตรายไม่ได้หมายความว่าทุกเหตุการณ์เป็นพฤติกรรมมัลแวร์ในตัวเอง จึงจำแนกความแรงของหลักฐานออกเป็นระดับ ตั้งแต่หลักฐานตรงในคอลัมน์ของเหตุการณ์เอง ไปจนถึงการติดป้ายเพราะสายเลือดล้วน
P040 3.5 การสร้างคุณลักษณะเชิงพฤติกรรม
P041 แต่ละกระบวนการ (จัดกลุ่มด้วย ProcessGuid ร่วมกับรหัสเครื่องและรอบทดลอง) ถูกแปลงเป็นเวกเตอร์คุณลักษณะเชิงตัวเลข 32 ตัว แบ่งเป็น 5 กลุ่มดังตาราง 2 การรวมเหตุการณ์เป็นสถิติระดับกระบวนการช่วยให้แบบจำลองวิเคราะห์พฤติกรรมจากหลายเหตุการณ์ร่วมกันแทนการพิจารณาเหตุการณ์เดี่ยว ทั้งนี้ต้องแยกกรณี “ไม่มีพฤติกรรมเกิดขึ้น” ออกจากกรณี “แหล่งข้อมูลไม่รองรับการเก็บพฤติกรรมนั้น” เนื่องจาก Windows และ Linux เก็บเหตุการณ์ได้ไม่เท่ากัน

P045 3.6 การลดมิติด้วย PCA และการเลือกคุณลักษณะ
P046 นำคุณลักษณะมาปรับมาตรฐานด้วย StandardScaler ก่อนศึกษาการลดมิติด้วย Principal Component Analysis (PCA) โดยกวาดจำนวนองค์ประกอบตั้งแต่ 1 ถึงจำนวนคุณลักษณะเต็ม แล้วเลือกค่าที่ให้ F1 สูงสุดบนชุด validation เพื่อป้องกันการรั่วไหลของข้อมูล พารามิเตอร์ของ StandardScaler และ PCA ถูกเรียนรู้จากชุด train เท่านั้น แล้วนำการแปลงเดียวกันไปใช้กับ validation และ test [2] นอกจากนี้ยังศึกษาการเลือกคุณลักษณะแบบตัดถอยหลังอย่างละโมบ (greedy backward elimination) เพื่อระบุว่าคุณลักษณะใดแบกสัญญาณจริง และเพื่อคัดคุณลักษณะที่สืบเนื่องจากกระบวนการกำหนดป้ายกำกับ (derived features) ออก ผลของทั้ง PCA และการเลือกคุณลักษณะรายงานในหัวข้อ 4.5 การจัดการความไม่สมดุลของคลาสพิจารณาใช้เทคนิค SMOTE [18] เฉพาะบนชุด train ขั้นตอนการกวาดจำนวนองค์ประกอบ PCA (ทำตามงานอ้างอิง [1]) แสดงเป็นผังงานในภาพ 2

P071 4.4 การวิเคราะห์การรั่วไหลของข้อมูล (Data Leakage)
P072 การรั่วไหลของข้อมูลเป็นประเด็นสำคัญที่สุดของบทความนี้ เนื่องจากทำให้ค่าที่รายงานดูดีเกินจริงโดยไม่ได้สะท้อนความสามารถจริงในการตรวจจับ [2], [3] เราจึงตรวจสอบแหล่งการรั่วไหลอย่างเป็นระบบสี่ประเภท (1) การรั่วไหลจากโปรโตคอลการประเมิน เมื่อเหตุการณ์จากกระบวนการเดียวกันปรากฏทั้งในชุดฝึกและชุดทดสอบ (2) การรั่วไหลระดับแพลตฟอร์ม จากรูปแบบค่าว่างของคอลัมน์ที่ต่างกันระหว่าง Windows และ Linux ทำให้แบบจำลองแยกแพลตฟอร์มได้เกือบสมบูรณ์ (ราว 100%) หากไม่ควบคุม หลังตัดคอลัมน์ที่รั่วออกความสามารถในการแยกแพลตฟอร์มลดลงเข้าใกล้ระดับการเดาสุ่ม (3) การรั่วไหลจากขั้นเติมข้อมูล (enrichment) เมื่อกระบวนการที่เกิดหลัง Sysmon มีบรรทัดคำสั่งแต่กระบวนการที่เกิดก่อนไม่มี ทำให้ “บรรทัดคำสั่งว่าง” กลายเป็นตัวชี้ป้ายกำกับโดยบังเอิญ และ (4) การรั่วไหลจากคุณลักษณะที่สืบเนื่องจากกระบวนการกำหนดป้ายกำกับ เช่น ไดเรกทอรีทำงาน (ซึ่งตรงกับไดเรกทอรีทดสอบที่ใช้ตัดสินป้ายกำกับ) และความลึกของสายกระบวนการ แนวทางนี้สอดคล้องกับงานอ้างอิง [1] ที่ตัดคอลัมน์ Image, ProcessGUID, ProcessId, timestamp และ host_name ออกด้วยเหตุผลเดียวกัน คือคอลัมน์เหล่านั้นสัมพันธ์โดยตรงกับตัวแปรเป้าหมาย
P073 ตาราง 6 แสดงความอ่อนไหวของค่าที่รายงานต่อโปรโตคอลการประเมินบนแบบจำลองและข้อมูลชุดเดียวกัน การแบ่งแบบสุ่มรายแถวให้ F1 สูงถึง 0.961 แต่เมื่อเปลี่ยนเป็นการแบ่งแบบจัดกลุ่มตามกระบวนการ ค่าลดลงเหลือ 0.811 และเมื่อประเมินแบบกันสถานการณ์ออก (zero-day) ลดลงเหลือ 0.634 ความต่างกว่า 30 จุดนี้เกิดจากข้อมูลชุดเดียวกันทุกแถว ต่างกันเพียงวิธีแบ่ง จึงยืนยันว่าการรายงานตัวเลขต้องระบุโปรโตคอลเสมอ

P077 4.5 ผลของการเลือกคุณลักษณะและ PCA
P078 การเลือกคุณลักษณะแบบตัดถอยหลังพบว่าคุณลักษณะเพียง 4-5 ตัวแบกสัญญาณส่วนใหญ่ อย่างไรก็ตาม คุณลักษณะเหล่านี้ส่วนมากไม่ใช่ “พฤติกรรม” แต่เป็นการรั่วไหลของท่อข้อมูล เช่น ไดเรกทอรีทำงานและความลึกของสายกระบวนการ ตาราง 7 แสดงว่าการตัดคุณลักษณะที่รั่ว (derived) ออกทำให้ F1 ลดลงเล็กน้อย (0.9475 → 0.9241) แต่เมื่อตัดคุณลักษณะความยาวคำสั่งออกด้วยจนเหลือเฉพาะพฤติกรรมล้วน F1 ลดลงมากถึง 0.610 ซึ่งชี้ว่าคะแนนส่วนหนึ่งมาจากความยาวคำสั่งของชุดทดสอบอัตโนมัติ ไม่ใช่พฤติกรรมที่ Sysmon เก็บ ข้อสังเกตนี้สอดคล้องกับงานอ้างอิง [1] ที่ตัดคอลัมน์ Image ทิ้งเพราะสัมพันธ์โดยตรงกับป้ายกำกับ บทความนี้จึงรายงานผลด้วยชุดคุณลักษณะที่ควบคุมการรั่วไหลแล้วเป็นหลัก และรายงานคู่กับชุดที่ไม่ควบคุมเพื่อความโปร่งใส

P088 5. อภิปรายผล
P089 ผลการทดลองสอดคล้องกับงานอ้างอิงในสองประเด็น คือ Random Forest ให้ผลดีที่สุดในกลุ่มมีผู้สอน และ Local Outlier Factor ดีที่สุดในกลุ่มไม่มีผู้สอน [1], [14] นอกจากนี้การจำแนกระดับกระบวนการให้ผลดีกว่าระดับเหตุการณ์เดี่ยวอย่างชัดเจน สอดคล้องกับ [9] เนื่องจากเหตุการณ์เดี่ยวของมัลแวร์มักคล้ายพฤติกรรมปกติ สิ่งที่จำแนกได้จริงคือรูปแบบรวมของกระบวนการ
P090 ประเด็นที่บทความนี้เน้นเป็นพิเศษคือความน่าเชื่อถือของการวัดผล เราแสดงเชิงประจักษ์ว่าค่าที่รายงานขึ้นกับ (1) โปรโตคอลการประเมิน (ตาราง 6) และ (2) ชุดคุณลักษณะที่เลือก (ตาราง 7) มากกว่าปริมาณข้อมูล ตามที่ [2], [3] เตือนไว้ การควบคุมการรั่วไหลของข้อมูลจึงสำคัญกว่าการเพิ่มจำนวนเหตุการณ์ และการลดมิติด้วย PCA ให้ประโยชน์จำกัดกับชุดข้อมูลนี้เพราะคุณลักษณะผ่านการเข้ารหัสมาแล้ว การรายงานตัวเลขจึงควรระบุทั้งโปรโตคอลและชุดคุณลักษณะเสมอ ข้อจำกัดของงานได้แก่ จำนวนเครื่องที่ใช้เก็บข้อมูลยังน้อย ความหลากหลายของพฤติกรรมปกติยังจำกัด (ทำให้คุณลักษณะความยาวคำสั่งแยกคลาสได้ง่ายเกินจริง) และการจำลองด้วย Atomic Red Team อาจให้พฤติกรรมน้อยกว่ามัลแวร์จริงในบางเหตุการณ์
P091 6. สรุปและงานในอนาคต
P092 บทความนี้นำเสนอชุดข้อมูล Sysmon แบบสองแพลตฟอร์มจำนวน 81,331 เหตุการณ์สำหรับการตรวจจับมัลแวร์ พร้อมวิเคราะห์การรั่วไหลของข้อมูลอย่างเป็นระบบ ภายใต้โปรโตคอลที่ป้องกันการรั่วไหล แบบจำลอง Random Forest ระดับกระบวนการให้ความแม่นยำ 94.9% และ F1 0.924 งานในอนาคตได้แก่ การเพิ่มความหลากหลายของพฤติกรรมปกติ การเพิ่มจำนวนเครื่องและรอบทดลองเพื่อเสริมความแข็งแรงของการประเมินแบบ zero-day และการหลอมรวมสัญญาณระดับเครือข่าย เข้ากับบันทึกโฮสต์เพื่อยกระดับการตรวจจับพฤติกรรม C2
