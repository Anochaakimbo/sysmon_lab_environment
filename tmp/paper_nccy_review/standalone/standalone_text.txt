การสร้างชุดข้อมูลข้ามแพลตฟอร์มสำหรับการตรวจจับมัลแวร์ด้วยการเรียนรู้ของเครื่องจากบันทึกเหตุการณ์ Sysmonบนระบบปฏิบัติการ Linux และ Windows
A CROSS-PLATFORM SYSMON-BASED DATASETFOR MACHINE-LEARNING MALWARE DETECTIONON LINUX AND WINDOWS

บทคัดย่อ
บทความนี้นำเสนอการสร้างและประเมินชุดข้อมูลบันทึกเหตุการณ์ Sysmon จาก Linux และ Windows สำหรับศึกษาการตรวจจับมัลแวร์ด้วยการเรียนรู้ของเครื่อง การทดลองใช้ Atomic Red Team จำลองห้ากลุ่มสถานการณ์โจมตีร่วมกับพฤติกรรมปกติ และกำหนดป้ายกำกับสถานการณ์โจมตีด้วยการสืบสายกระบวนการ ชุดข้อมูลประกอบด้วย 81,331 เหตุการณ์ 80 คอลัมน์ และมีเหตุการณ์ที่กำหนดป้ายกำกับอันตราย 33.8% เมื่อนำเหตุการณ์มารวมเป็นคุณลักษณะระดับกระบวนการและตัดคุณลักษณะที่เกี่ยวข้องกับขั้นเติมข้อมูลออก เหลือคุณลักษณะ 32 ตัว ผลเบื้องต้นจากการแบ่ง holdout ตาม ProcessGuid ด้วย GroupShuffleSplit สัดส่วน 70:30 พบว่า Random Forest ให้ Accuracy 94.9%, F1 0.924 และ ROC-AUC 0.988 ส่วน Local Outlier Factor ให้ F1 0.714 และ ROC-AUC 0.849 การประเมินเพิ่มเติมโดยกันคู่แพลตฟอร์ม–สถานการณ์ออกทีละกลุ่มให้ F1 เฉลี่ยของ Random Forest เท่ากับ 0.764 ผลสะท้อนความสามารถในการจำแนกภายในแล็บ และแสดงความจำเป็นของการระบุหน่วยตัวอย่าง วิธีแบ่งข้อมูล และขอบเขตการประเมินอย่างชัดเจน การยืนยันผลภายนอกแล็บยังต้องเพิ่มรอบเก็บ เครื่องเป้าหมาย และการทดสอบกับมัลแวร์จริง
คำสำคัญ -- Sysmon, การตรวจจับมัลแวร์, ชุดข้อมูลข้ามแพลตฟอร์ม, คุณลักษณะระดับกระบวนการ, การประเมินแบบจัดกลุ่ม
ABSTRACT
This paper presents a cross-platform Sysmon dataset for studying machine-learning malware detection on Linux and Windows. Atomic Red Team emulates five attack scenario categories alongside benign activity. Attack-session labels are assigned through process lineage. The dataset contains 81,331 events and 80 columns, with 33.8% of events labeled malicious. Process aggregation and removal of enrichment-related features produce 32 features for classification. In a single 70:30 process holdout using GroupShuffleSplit, preliminary results show that Random Forest achieves 94.9% accuracy, an F1 score of 0.924, and a ROC-AUC of 0.988. Local Outlier Factor achieves an F1 score of 0.714 and a ROC-AUC of 0.849. Additional holdouts of individual platform-scenario combinations yield a mean Random Forest F1 score of 0.764. These results characterize performance within the laboratory and highlight the need to report the sample unit, split protocol, and evaluation scope. Further validation requires independent collection runs, additional hosts, and real malware samples.
Keywords -- Sysmon, malware detection, cross-platform dataset, process-level features, grouped evaluation
1. บทนำ
การตรวจจับมัลแวร์เชิงพฤติกรรมอาศัยการสังเกตกิจกรรมขณะโปรแกรมทำงาน เช่น การสร้างกระบวนการ การเขียนไฟล์ และการติดต่อเครือข่าย บันทึกจาก System Monitor หรือ Sysmon ช่วยรวบรวมกิจกรรมเหล่านี้พร้อมข้อมูลของกระบวนการที่เกี่ยวข้อง [1] อย่างไรก็ตาม เหตุการณ์เพียงรายการเดียวอาจเกิดได้ทั้งจากโปรแกรมปกติและโปรแกรมที่เกี่ยวข้องกับการโจมตี การรวมเหตุการณ์ของกระบวนการจึงเป็นแนวทางสำหรับศึกษารูปแบบการทำงานตลอดช่วงเวลาที่สังเกต
การสร้างชุดข้อมูลสำหรับงานนี้ต้องพิจารณาทั้งความแตกต่างของระบบปฏิบัติการและความสัมพันธ์ระหว่างตัวอย่าง Windows และ Linux มีรูปแบบคำสั่ง เส้นทางไฟล์ และการรองรับเหตุการณ์ต่างกัน ขณะเดียวกัน เหตุการณ์จากกระบวนการหรือรอบทดลองเดียวกันอาจมีลักษณะคล้ายกันมาก หากแบ่งตัวอย่างโดยไม่คำนึงถึงความสัมพันธ์เหล่านี้ ผลทดสอบอาจสะท้อนการจดจำสภาพแวดล้อมมากกว่าความสามารถในการจำแนกพฤติกรรม ประเด็นดังกล่าวเกี่ยวข้องกับอคติและการรั่วไหลของข้อมูลที่งานด้านความมั่นคงปลอดภัยเชิงเรียนรู้ให้ความสำคัญ [2], [3]
งานวิจัยนี้ตั้งโจทย์ว่าบันทึก Sysmon จากสองแพลตฟอร์มสามารถนำมารวมเป็นชุดข้อมูลระดับกระบวนการเพื่อศึกษาการจำแนกกิจกรรมปกติและกิจกรรมที่เกี่ยวข้องกับการโจมตีได้อย่างไร และผลการประเมินเปลี่ยนแปลงอย่างไรเมื่อเปลี่ยนวิธีแบ่งข้อมูล การทดลองจัดสถานการณ์ตามกลุ่มพฤติกรรมในกรอบ MITRE ATT&CK [4] และใช้ Atomic Red Team [5] ภายใต้แล็บที่ควบคุมการเก็บบันทึกและการกำหนดป้ายกำกับ
ส่วนสนับสนุนของงานประกอบด้วยการสร้างชุดข้อมูล Sysmon จาก Linux และ Windows ภายใต้ประเภทสถานการณ์ร่วมกัน การกำหนดป้ายกำกับโดยเชื่อมโยงกระบวนการที่เริ่มจากชุดทดสอบกับลูกหลาน การสร้างสถิติระดับกระบวนการที่รวมกิจกรรมหลายเหตุการณ์ และการประเมินแบบจำลองภายใต้การแบ่งตามกระบวนการและการกันคู่แพลตฟอร์ม–สถานการณ์ออก ผลที่รายงานใช้ระบุสมรรถนะและข้อจำกัดของชุดข้อมูลภายในแล็บ เพื่อเป็นพื้นฐานสำหรับการเก็บและประเมินข้อมูลรอบถัดไป
2. งานที่เกี่ยวข้อง
2.1 บันทึก Sysmon และข้อมูลข้ามแพลตฟอร์ม
Mahmoud และคณะ [6] ศึกษาการวิเคราะห์มัลแวร์ด้วย Sysmon ร่วมกับระบบ ELK เพื่อรวบรวมและวิเคราะห์กิจกรรมบนเครื่อง ส่วน BarongTrace [7] นำเสนอชุดข้อมูลเหตุการณ์มัลแวร์บน Linux งานทั้งสองแสดงแนวทางการใช้บันทึกระดับโฮสต์ในสภาพแวดล้อมต่างกัน สำหรับงานนี้ บันทึกจากแต่ละแพลตฟอร์มถูกแปลงเป็นตารางร่วมกัน โดยยังเก็บรหัสแพลตฟอร์ม เครื่อง และรอบทดลองไว้สำหรับตรวจสอบย้อนกลับ
2.2 การวิเคราะห์พฤติกรรมและหน่วยกระบวนการ
Sgandurra และคณะ [8] ศึกษาการตรวจจับ ransomware จากพฤติกรรมที่เก็บระหว่างการทำงานของโปรแกรม และ Herrera-Silva กับ Hernandez-Alvarez [9] นำเสนอชุดข้อมูลคุณลักษณะเชิงพลวัตสำหรับ ransomware ส่วน Pratomo และคณะ [10] ศึกษาการวิเคราะห์มัลแวร์ในระดับเครื่องและระดับกระบวนการ งานนี้ใช้กระบวนการเป็นหน่วยวิเคราะห์เพื่อเชื่อมจำนวนเหตุการณ์ กิจกรรมไฟล์ เครือข่าย และช่วงเวลาการทำงานเข้าด้วยกัน แทนการตัดสินจากเหตุการณ์รายการเดียว
2.3 ข้อมูลสืบสายและความน่าเชื่อถือของการประเมิน
UNICORN [11] และ Kairos [12] ใช้ข้อมูล provenance เพื่อวิเคราะห์ความสัมพันธ์ระหว่างกิจกรรมในระบบ งานนี้ใช้ความสัมพันธ์ของกระบวนการแม่และลูกในขั้นกำหนดป้ายกำกับ เพื่อระบุว่ากิจกรรมใดเชื่อมโยงกับกระบวนการเริ่มต้นของการทดลอง ขณะเดียวกัน ข้อเสนอแนะเรื่องอคติในการประเมิน [2], [3] เป็นเหตุผลให้รายงานวิธีแบ่งข้อมูลอย่างชัดเจน และแยกการทดสอบกระบวนการที่กันออกจากการทดสอบรอบเก็บหรือเครื่องที่ไม่เคยใช้ในการฝึก
3. ระเบียบวิธีวิจัย
กระบวนการทดลองเริ่มจากการจำลองกิจกรรมและเก็บบันทึก Sysmon จากนั้นแยกวิเคราะห์ เติมข้อมูลกระบวนการ กำหนดป้ายกำกับ และสร้างคุณลักษณะระดับกระบวนการ ก่อนแบ่งชุดข้อมูลและฝึกแบบจำลอง ภาพ 1 แสดงลำดับของการทดลอง holdout หลัก การประเมินแบบกันคู่แพลตฟอร์ม–สถานการณ์ออกดำเนินแยกตามกลุ่มที่ระบุในหัวข้อ 3.6


ภาพ 1 กระบวนการเตรียมข้อมูลและประเมินด้วย holdout ระดับกระบวนการ

3.1 สภาพแวดล้อมและการเก็บบันทึก
การทดลองใช้ VMware Workstation และ Vagrant จัดการเครื่องเสมือน Linux และ Windows บนโฮสต์ Windows 11 เครื่อง Linux ใช้ Ubuntu 22.04 และ Sysmon for Linux โดยส่งบันทึกผ่าน journald และ rsyslog ด้วย TCP ไปยังโฮสต์ ส่วน Windows เก็บบันทึกจาก Sysmon และส่งออกหลังจบสถานการณ์ เครื่องเสมือนทำงานทีละเครื่อง และคืนสภาพ snapshot ก่อนเริ่มสถานการณ์เพื่อควบคุมสภาพแวดล้อม
กิจกรรมปกติและกิจกรรมโจมตีของแต่ละแพลตฟอร์มเก็บบนเครื่องเป้าหมายเดียวกัน การตั้งค่าแล็บฝั่ง Windows ปิด Defender เพื่อให้ชุดทดสอบทำงานได้ จึงต้องพิจารณาการตั้งค่านี้เมื่อประเมินการนำผลไปใช้ในระบบจริง ข้อมูลปัจจุบันมีหนึ่งรอบเก็บต่อสถานการณ์ต่อแพลตฟอร์ม รวม 12 รอบ รหัสรอบทดลองถูกเก็บไว้ในคอลัมน์ run_id
3.2 สถานการณ์และการจำลองพฤติกรรม
แต่ละแพลตฟอร์มมีพฤติกรรมปกติและห้ากลุ่มสถานการณ์โจมตี ได้แก่ ransomware, trojan, botnet, cryptominer และ exploitation ดังตาราง 1 ชุดทดสอบ Atomic Red Team จำลองเทคนิคที่เกี่ยวข้องตามกรอบ MITRE ATT&CK โดยมีเซิร์ฟเวอร์ Command-and-Control และ mining pool ภายในแล็บสำหรับกิจกรรมเครือข่าย ชื่อกลุ่มเหล่านี้ระบุประเภทสถานการณ์จำลอง ไม่ใช่การยืนยันตระกูลของมัลแวร์จริง
ตาราง 1 ประเภทสถานการณ์และตัวอย่างพฤติกรรม
สถานการณ์labelตัวอย่างพฤติกรรมBenign0กิจกรรมผู้ใช้ปกติRansomware1แก้ไขไฟล์จำนวนมากTrojan1การคงอยู่และแก้ registryBotnet1ติดต่อเซิร์ฟเวอร์ควบคุมCryptominer1ใช้ทรัพยากรและต่อ mining poolExploitation1จำลองการใช้ช่องโหว่และยกระดับสิทธิ์
3.3 การประมวลผลและการกำหนดป้ายกำกับ
บันทึกของทั้งสองแพลตฟอร์มผ่านขั้นแยกวิเคราะห์ เติมข้อมูล และกำหนดป้ายกำกับ ขั้นแยกวิเคราะห์แปลงข้อมูลเหตุการณ์เป็นตาราง ขั้นเติมข้อมูลเชื่อมข้อมูลที่เกี่ยวข้องกับกระบวนการ เช่น บรรทัดคำสั่งและข้อมูลกระบวนการแม่ ก่อนรวมข้อมูลจากทุกรอบเป็นไฟล์เดียว คอลัมน์ที่ระบุเครื่อง แพลตฟอร์ม และรอบทดลองเก็บไว้สำหรับตรวจสอบที่มาและกำหนดกลุ่มประเมิน
ในรอบสถานการณ์โจมตี กำหนดกระบวนการเริ่มต้นจากตำแหน่งไฟล์หรือคำสั่งของชุดทดสอบ แล้วติดตามกระบวนการลูกที่สืบสายจากกระบวนการเริ่มต้น เหตุการณ์ที่เชื่อมโยงได้กำหนด label=1 ส่วนเหตุการณ์ที่ไม่อยู่ในสายดังกล่าวกำหนด label=0 รอบพฤติกรรมปกติกำหนด label=0 ตามรอบทดลอง ในข้อมูลรวมมี 62,035 เหตุการณ์ที่ใช้วิธี lineage และ 19,296 เหตุการณ์ที่ใช้วิธี session โดยเหตุการณ์จากวิธี session ทั้งหมดมี label=0
ป้ายกำกับอันตรายในงานนี้หมายถึงความสัมพันธ์กับกระบวนการทดลองโจมตี การมี label=1 จึงไม่ได้หมายความว่าทุกเหตุการณ์เป็นการกระทำอันตรายในตัวเอง คอลัมน์ label_method และ is_seed ช่วยตรวจสอบกติกาที่ใช้กำหนดป้ายกำกับ ความถูกต้องของป้ายกำกับยังต้องตรวจสอบร่วมกับรายละเอียดการทำงานของชุดทดสอบ
3.4 การสร้างคุณลักษณะระดับกระบวนการ
การรวมข้อมูลปัจจุบันใช้ ProcessGuid เป็นกุญแจและตัดแถวที่ไม่มีค่านี้ก่อนสร้างเวกเตอร์ ได้ 23,971 แถว แต่ละแถวใช้ label สูงสุดของเหตุการณ์ในกลุ่มเป็นป้ายกำกับ กระบวนการที่มีเหตุการณ์ label=1 อย่างน้อยหนึ่งรายการจึงมีป้ายกำกับเป็น 1 ข้อจำกัดของการใช้ GUID เพียงคอลัมน์เดียวและการจัดการ GUID ศูนย์อธิบายในหัวข้อ 5.2
สร้างคุณลักษณะเริ่มต้น 35 ตัว ได้แก่ จำนวนเหตุการณ์ จำนวนและสัดส่วนเหตุการณ์แต่ละชนิด จำนวนค่าปลายทางที่ต่างกัน ระยะเวลาที่สังเกต อัตราเหตุการณ์ ความยาวคำสั่งและเส้นทางโปรแกรม รวมถึงข้อมูลจากขั้นเติมข้อมูล ผลหลักตัด img_len, depth และ enriched ออก เหลือ 32 ตัวตามตาราง 2 ชุดคุณลักษณะนี้ไม่มีจำนวนกระบวนการลูกหรือค่า IntegrityLevel โดยตรง การสืบสายใช้ในขั้นกำหนดป้ายกำกับและไม่ได้เป็นคุณลักษณะกราฟที่ป้อนโมเดล
ตาราง 2 องค์ประกอบของคุณลักษณะระดับกระบวนการ 32 ตัว
กลุ่มคุณลักษณะจำนวนปริมาณn_events1ชนิดเหตุการณ์ev_ID และ frac_ID สำหรับ EventID 11 ชนิด22ค่าที่แตกต่างn_files, n_dst_ip, n_dst_port, n_regobj, n_device5เวลาและอัตราdur_s และ rate2คำสั่งcmd_len และ pcmd_len2รวม32
สถิติระยะเวลาคำนวณจากเวลาสุดท้ายลบเวลาแรกในกลุ่ม และอัตราเหตุการณ์หารด้วยระยะเวลาอย่างน้อยหนึ่งวินาที ค่าที่ไม่มีข้อมูลถูกเติมเป็น 0 ตามกฎปัจจุบัน ส่วนความยาวคำสั่งคำนวณจากค่าคำสั่งแรกที่มีในกลุ่ม การเติม 0 ยังไม่แยกระหว่างการไม่เกิดเหตุการณ์กับการไม่รองรับเหตุการณ์ของแพลตฟอร์ม จึงต้องคำนึงถึงข้อจำกัดนี้เมื่อตีความคุณลักษณะ
3.5 แบบจำลองและการเตรียมข้อมูล
พัฒนาและประเมินแบบจำลองด้วย scikit-learn [13] ผลหลักใช้คุณลักษณะทั้ง 32 ตัวโดยไม่ใช้ PCA และปรับมาตรฐานด้วย StandardScaler ซึ่งเรียนรู้ค่าจากชุดฝึกภายนอกแล้วใช้การแปลงเดียวกันกับชุดทดสอบ แบบมีผู้สอนประกอบด้วย Naive Bayes, Decision Tree, Random Forest [14] และ SVM [15] โดย Decision Tree, Random Forest และ SVM ใช้ class_weight แบบ balanced ส่วน Naive Bayes ใช้ GaussianNB
กำหนดพารามิเตอร์คงที่สำหรับการทดลองหลัก Random Forest ใช้ต้นไม้ 70 ต้น min_samples_leaf=9, max_features=sqrt และ bootstrap=False; Decision Tree ใช้ criterion=entropy, max_depth=17, min_samples_split=14, min_samples_leaf=5 และ max_features=log2; SVM ใช้ RBF kernel, C=10 และ gamma=scale; GaussianNB ใช้ var_smoothing=10 ยกกำลัง −8 ค่าดังกล่าวเป็น configuration ของผลที่รายงาน ไม่ใช่ผลค้นหาพารามิเตอร์ที่ดีที่สุดบนชุดข้อมูลนี้
แบบไม่มีผู้สอนประกอบด้วย Isolation Forest [16], Local Outlier Factor [17] และ One-Class SVM [18] ซึ่งฝึกด้วยกระบวนการ label=0 เท่านั้น Isolation Forest ใช้ต้นไม้ 200 ต้น; Local Outlier Factor ใช้เพื่อนบ้าน 20 ตัวและ novelty=True; One-Class SVM ใช้ RBF kernel และตัวอย่างฝึกปกติไม่เกิน 6,000 แถว การทดลองหลักเริ่มด้วย contamination หรือ nu เท่ากับ 0.1 และกำหนด random seed=0 ในขั้นที่รองรับ
สำหรับการเลือกค่าตัด แบ่งข้อมูลฝึกภายนอกเป็นส่วนย่อย 75:25 ตามกระบวนการ แล้วเลือกสัดส่วน quantile ที่ให้ F1 สูงสุดบนส่วน validation โดยกวาดตั้งแต่ 0.05 ถึง 0.60 ครั้งละ 0.05 ผลหลักเลือกสัดส่วน 0.45 และใช้ quantile ของคะแนนข้อมูลฝึกทั้งหมดเป็นค่าตัดสุดท้าย วิธีปัจจุบัน fit scaler และโมเดลไม่มีผู้สอนก่อนแยกคะแนน validation จึงมีข้อมูลปกติจากส่วน validation อยู่ในการ fit ด้วย ผลส่วนนี้ควรตีความเป็นผลเบื้องต้น และต้องยืนยันด้วยชุด calibration ที่เป็นอิสระ
3.6 การแบ่งข้อมูลและตัวชี้วัด
ผลหลักใช้ GroupShuffleSplit ตาม ProcessGuid หนึ่งครั้ง สัดส่วนฝึกต่อทดสอบ 70:30 และ random seed=0 ได้ชุดฝึก 16,779 แถวและชุดทดสอบ 7,192 แถว โดยมี label=1 จำนวน 5,612 และ 2,399 แถวตามลำดับ ไม่มี ProcessGuid เดียวกันข้ามชุด การแบ่งนี้ลดการทดสอบด้วยเหตุการณ์จากกระบวนการเดียวกับที่ฝึก แต่ยังมีความสัมพันธ์ระหว่างกระบวนการจากสายหรือรอบทดลองเดียวกันได้
การประเมินเพิ่มเติมสร้างกลุ่มจากแพลตฟอร์มร่วมกับชื่อสถานการณ์ และกันกลุ่มโจมตีออกทีละกลุ่มรวม 10 กลุ่ม โดยไม่กันกลุ่ม benign ออก ตัวอย่างเช่น เมื่อกัน ransomware บน Linux ออก ชุดฝึกยังมี ransomware บน Windows การประเมินนี้จึงศึกษาคู่แพลตฟอร์ม–สถานการณ์ที่กันออก ภายในแล็บ ไม่ใช่การกันการโจมตีชนิดเดียวกันออกจากทั้งสองแพลตฟอร์ม ในการประเมินนี้โมเดลไม่มีผู้สอนใช้ contamination หรือ nu เท่ากับ 0.3 โดยไม่ปรับค่าตัดแบบการทดลองหลัก
รายงาน Accuracy, Precision, Recall, F1 และ ROC-AUC โดยกำหนด label=1 เป็นคลาสบวก F1 เป็นค่าเฉลี่ยฮาร์มอนิกของ Precision และ Recall ส่วน ROC-AUC คำนวณจากคะแนนต่อเนื่องของแบบจำลอง นอกจากนี้ใช้วิธีแจ้งเตือนทุกแถวเป็นเส้นฐานภายใน เพื่อให้เห็นว่าค่า Recall สูงเพียงอย่างเดียวเพียงพอต่อการจำแนกหรือไม่ ผลการกันกลุ่มออกสรุปเป็นค่าเฉลี่ยรายกลุ่ม และนับจำนวนกลุ่มที่ F1 สูงกว่าวิธีแจ้งเตือนทุกแถว

5. อภิปรายผลและข้อจำกัด
5.1 การตีความผลภายในแล็บ
ผล process holdout แสดงว่าเวกเตอร์สถิติที่สร้างจากบันทึก Sysmon มีข้อมูลสำหรับแยกป้ายกำกับภายในแล็บนี้ Random Forest ให้ Precision และ Recall ใกล้กัน ขณะที่ Local Outlier Factor จำแนกจากรูปแบบข้อมูลปกติได้โดยไม่ใช้ label=1 ในการฝึก อย่างไรก็ตาม ข้อมูลมาจากสถานการณ์จำลองและพฤติกรรมปกติที่จำกัด ความยาวคำสั่งหรือกิจกรรมของชุดทดสอบอาจมีรูปแบบเฉพาะ จึงยังต้องประเมินว่าสัญญาณที่แบบจำลองใช้คงอยู่ในโปรแกรมและรอบทดลองอื่นหรือไม่
การใช้ข้อมูลสองแพลตฟอร์มทำให้ชุดข้อมูลมีบริบทของกิจกรรมหลายระบบปฏิบัติการ แต่ไม่ได้รับรองว่าแบบจำลองเป็นอิสระจากแพลตฟอร์ม สัดส่วนคลาสระดับกระบวนการและรูปแบบข้อมูลที่ขาดต่างกันระหว่างสองระบบ การยืนยันความสามารถข้ามแพลตฟอร์มต้องออกแบบการฝึกและทดสอบแยกตามแพลตฟอร์ม พร้อมควบคุมประเภทสถานการณ์และหน่วยตัวอย่าง ส่วนผลความอ่อนไหวในตาราง 6 สนับสนุนให้รายงานวิธีแบ่งข้อมูลทุกครั้ง และไม่ได้พิสูจน์ว่าวิธีใดมีผลมากกว่าปริมาณข้อมูล
5.2 ข้อจำกัดของข้อมูลและการประเมิน
ข้อมูลมีหนึ่งรอบต่อสถานการณ์ต่อแพลตฟอร์มและมีเครื่องเป้าหมายจำกัด การแบ่งตามกระบวนการยังอาจมีสายแม่–ลูกหรือกิจกรรมจากรอบเดียวกันอยู่ทั้งสองชุด ส่วนการกันคู่แพลตฟอร์ม–สถานการณ์ออกยังมีประเภทสถานการณ์เดียวกันจากอีกระบบอยู่ในชุดฝึก จึงต้องเพิ่มการทดสอบข้ามรอบ ข้ามเครื่อง และการกันสถานการณ์ชนิดเดียวกันออกจากทั้งสองระบบก่อนสรุปความสามารถต่อสภาพแวดล้อมที่ไม่เคยพบ
การรวมด้วย ProcessGuid เพียงคอลัมน์เดียวมีข้อจำกัดเมื่อ GUID ซ้ำระหว่างรอบ ในข้อมูลพบ GUID ศูนย์จำนวน 612 เหตุการณ์กระจายหลายรอบ และมี GUID จริงหนึ่งค่าซ้ำใน Linux exploit และ miner รวม 12 เหตุการณ์ นอกจากนี้แปดเหตุการณ์ไม่มี GUID การแก้ในรอบถัดไปควรใช้กุญแจร่วมของแพลตฟอร์ม เครื่อง รอบเก็บ และ GUID พร้อมกำหนดวิธีจัดการ GUID ศูนย์และเหตุการณ์ที่ใช้ SourceProcessGuid หรือ TargetProcessGuid แล้วสร้างคุณลักษณะและประเมินใหม่
การเลือกค่าตัดของโมเดลไม่มีผู้สอนใช้ส่วน validation ที่มีข้อมูลปกติร่วมกับการ fit และค่าตัดสุดท้ายอ้าง quantile ของคะแนน train ต่างจาก quantile ที่ใช้เลือกบน validation ผลด้านนี้จึงต้องยืนยันด้วยการแยก fit และ calibration ก่อนเรียนรู้ preprocessing และโมเดล โดยตรึงค่าตัดก่อนทดสอบ รวมทั้งรายงาน confusion matrix และอัตราการแจ้งเตือนผิด ผลหลักปัจจุบันเป็นผลจากการแบ่งครั้งเดียว จึงยังไม่มีช่วงความเชื่อมั่นจากรอบเก็บอิสระ
ความครบถ้วนของ lineage และกฎกำหนดป้ายกำกับมีผลต่อความหมายของคลาส การติดตามลูกหลานยืนยันความเชื่อมโยงกับการทดลองได้ แต่ควรตรวจตัวอย่างเหตุการณ์ร่วมกับหลักฐานจากชุดทดสอบ นอกจากนี้ต้องตรวจการแทนค่าคำสั่งที่หายไป การรองรับชนิดเหตุการณ์ของแต่ละแพลตฟอร์ม และผลของการปิด Defender ต่อองค์ประกอบข้อมูล เพื่อให้การประเมินภายหลังสะท้อนการใช้งานที่ต้องการ
6. สรุปและงานในอนาคต
งานนี้สร้างชุดข้อมูล Sysmon จาก Linux และ Windows จำนวน 81,331 เหตุการณ์ พร้อมกฎกำหนดป้ายกำกับและคุณลักษณะระดับกระบวนการ 32 ตัว ผลเบื้องต้นจาก process holdout หนึ่งครั้งให้ Random Forest มี Accuracy 94.9% และ F1 0.924 ส่วน Local Outlier Factor ให้ F1 0.714 การประเมินโดยกันคู่แพลตฟอร์ม–สถานการณ์ออกให้ F1 เฉลี่ยของ Random Forest 0.764 ผลทั้งหมดควรตีความภายในเงื่อนไขการเก็บและการประเมินที่ระบุ
งานต่อไปควรแก้กุญแจรวมกระบวนการ แยก fit และ calibration ให้เป็นอิสระ เก็บแต่ละสถานการณ์ซ้ำจากหลายเครื่อง และเพิ่มความหลากหลายของกิจกรรมปกติกับมัลแวร์จริง จากนั้นประเมินข้ามรอบและข้ามแพลตฟอร์ม พร้อมวัดภาระการแจ้งเตือนผิด เพื่อให้เห็นว่ารูปแบบที่เรียนรู้จากแล็บสามารถนำไปใช้กับข้อมูลใหม่ได้เพียงใด
